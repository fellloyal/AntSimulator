# 统一地形/障碍/食物纹理渲染 计划

## 背景

用户反馈：地形、食物、障碍物的纹理渲染只在 MapEditor 出现，地图选择界面（GameSetup）和游戏界面（Simulator）均没有。

## 现状分析

### 三个页面的渲染路径

| 页面 | 渲染函数 | 是否使用 SVG 纹理 |
|---|---|---|
| MapEditor | 自有 paint + draw 循环 | ✅ TerrainRenderer / ObstacleRenderer / FoodPileRenderer |
| GameSetup | 简化的 `ctx.fillRect`（灰墙 + 绿食） | ❌ 无 |
| Simulator (Worker 路径) | `WorkerRenderer.renderWorld` 用 `#726b6b` / `rgb(0,g,0)` fillRect | ❌ 无 |
| Simulator (主线程路径) | `Renderer.render` | ✅ 已用 SVG 纹理，但默认走 Worker 路径 |

### 根因

1. **GameSetup.tsx** 早期实现仅作"占位预览"，未集成三个渲染器。
2. **WorkerRenderer** 接收的 `worldData: Float32Array`（每 cell 4 floats：packed、markerR/G/B）**不含** terrain、obstacle、foodType、wearLevel 字段，因此即使 WorldGrid 内部已存这些字段（来自 `UI美化` task 7-9），也传不到主线程。

## 方案

### A. 扩展 worker 协议传输新字段

`src/simulation/worker-protocol.ts`：
- `WORLD_FLOATS_PER_CELL`：4 → 8
- 布局：`[packed, markerR, markerG, markerB, terrain, obstacle, foodType, wearLevel]`
- `WORLD_DIRTY_FLOATS_PER_CELL`：5 → 9

`src/simulation/simulation-worker.ts`：
- `serializeCellData` 返回 8 个值
- full / dirty 两个序列化循环写入新字段

### B. WorkerRenderer 用 SVG 渲染

`src/render/WorkerRenderer.ts`：
- 预加载 SVG 纹理键（地形 4 种 + 障碍 4 种 + 食物 4 种），借助 AssetRegistry
- `renderWorld` 改为：
  1. 先按 terrain 分桶一次性 drawImage 地形纹理
  2. 再按 obstacle 分桶画障碍纹理（跳过 terrain=2 水）
  3. 再按 foodType 用 NxN 锚点法画食物精灵
  4. 颜色标记层（markers）保留，作为顶层覆盖

### C. 新增 MapPreviewRenderer，GameSetup 复用

新增 `src/render/MapPreviewRenderer.ts`：
- 输入：解析后的 gridData（包含 `cellSize, walls, foods, terrain`）和 viewport
- 内部直接调 AssetRegistry 绘制
- 与 WorkerRenderer 共享同一个 AssetRegistry 实例，纹理只需加载一次

`src/pages/GameSetup.tsx`：
- 用 MapPreviewRenderer 替换原 `fillRect` 墙/食逻辑
- 保留 colony 圆圈和地图边框的逻辑

## 修改文件

1. `src/simulation/worker-protocol.ts`：扩字段
2. `src/simulation/simulation-worker.ts`：序列化新字段
3. `src/render/WorkerRenderer.ts`：用 SVG 渲染
4. `src/render/MapPreviewRenderer.ts`（新增）
5. `src/pages/GameSetup.tsx`：用新渲染器

## 验证

- `npm run check`
- dev server 启动，浏览器自测：
  - 编辑器界面：地形/障碍/食物纹理正常（回归）
  - 选择地图：地图预览出现地形（沙/草/水）+ 障碍纹理 + 食物 Twemoji
  - 进入游戏：地形/障碍/食物纹理同编辑器一致
