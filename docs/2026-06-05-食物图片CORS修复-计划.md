# 食物图片 CORS 修复 - 2026-06-05

## 背景

上一会话把 4 种食物改用 `text_to_image` API 在线生成。但用户报告"看不到食物图"。

## 根因分析

`text_to_image` API 服务器对带 `Origin` 头的跨域请求返回 **403 禁止**：

```powershell
# 不带 Origin 头 → 200 OK + 176KB JPEG
Invoke-WebRequest "https://trae-api-cn.mchost.guru/...?prompt=...&image_size=square"  → 200

# 带 Origin 头 → 403 禁止
Invoke-WebRequest "..." -Headers @{Origin="http://localhost:5173"}  → 403
```

浏览器的 `<img>` 跨域加载会自动带 `Origin` 头，所以图片加载在浏览器中静默失败，console 报错为 `Failed to load image`。`AssetRegistry` 中 `img.onerror` 静默 resolve，导致缓存 canvas 留空，`drawTile` 画到画布上没有内容 → 看不到食物。

**关键发现**：在下载测试时还发现 API 对部分单词有过滤。`apple`、`chicken`、`bread`、`berry` 等单关键词会返回固定的默认图（176626 字节，hash `19A0B822...`），而 `red apple`、`fried chicken`、`bread loaf`、`blueberries` 等多词短语能返回正常生成的图。

## 修复方案

**运行时调用 → 离线生成 + 构建期嵌入**

1. 用 PowerShell `Invoke-WebRequest` 离线下载 4 张食物 JPG（每张 100-300KB）
2. 把 JPG 放进 `src/render/assets/food_images/`
3. 用 Vite `?url` 引入，得到同源 URL（同主机、同端口），**完全无 CORS 问题**
4. 提示词从冗长描述改为简洁多词短语，避开 API 的关键词过滤

```ts
// FoodSprites.ts
import appleUrl from './food_images/apple.jpg?url';
import chickenUrl from './food_images/chicken.jpg?url';
import breadUrl from './food_images/bread.jpg?url';
import berryUrl from './food_images/berry.jpg?url';
```

## 提示词

| 食物 | 提示词 | 文件大小 |
|------|------|------|
| 苹果 | `red apple with green leaf and brown stem` | 142 KB |
| 鸡腿 | `fried chicken drumstick with white bone` | 224 KB |
| 面包 | `golden bread loaf with score marks` | 188 KB |
| 浆果 | `blueberries cluster with green leaves` | 182 KB |

## 修改的文件

- `src/render/assets/FoodSprites.ts` — 改用 `?url` 引入本地 JPG
- `src/pages/MapEditor.tsx` — 移除未使用的 `FOOD_SPRITES` 导入
- `src/render/assets/food_images/{apple,chicken,bread,berry}.jpg` — 新增 4 张食物图

## 验证

- `npm run check` 通过
- Vite dev server 在 5173 端口正常服务 JPG（200 OK, 142391 字节）

## 经验

- **跨域 API 资源加载** → 优先采用"构建期下载 + 同源打包"，避免依赖服务器 CORS 配置
- **AI 图片生成 API** → 短关键词可能被过滤，多词具体描述更可靠
- **静默失败的图片加载** → 调试时应在 `img.onerror` 中打印 `key` 与 URL，便于定位问题
