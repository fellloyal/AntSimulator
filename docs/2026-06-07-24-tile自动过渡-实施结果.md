## 资源覆盖

**96 张 SVG 子瓦片**：
- 4 地形 × 16 边变体（mask 0-15）= 64 张
- 4 地形 × 4 角点 × 2 variant（convex/concave）= 32 张
- 每张 viewBox 8×8 或 20×20，尺寸匹配现有 TerrainTiles

**生成方式**：程序化生成（脚本），无手画依赖
- 草尖：`M2,18 L4,8` 风格的 path
- 沙粒：`<circle>` 散落
- 水波：`<path>` 波浪
- 石头裂纹：`<polygon>` + `<path>`

**色彩继承**：与 `TERRAIN_TILES` 保持一致（grass `#3a5a20`，sand `#c9a866` 等），但 96 张颜色用脚本里写死的 TERRAINS 数组，**没从 `TerrainTiles.ts` 读取**——这是一个待优化的耦合点。

## 渲染流程

### 主体（按 mask 分桶）
1. 遍历可见 cell 范围
2. 用 `computeEdgeMask()` 计算 4 邻居的位掩码
3. 按 `(terrain, edgeMask)` 分桶（避免重复绘制同一 SVG）
4. 桶内 cell 用 `AssetRegistry.drawTile()` 批量画 4×4 主体瓦片

### 角点（按需绘制）
1. 遍历可见 cell 范围
2. 用 `computeCornerMask()` + `computeAllCorners()` 判断 4 角点是否触发
3. 触发的角点（凸/凹）画 8×8 角贴片在对应 cell 角位置

**性能预估**（100×100 地图，~10000 cell）：
- 主体遍历：10000 × 8 次 getTerrainAt = ~80000 操作（~2-3ms）
- 角点遍历：10000 × 13 次 getTerrainAt = ~130000 操作（~4-5ms）
- 总计：~7-8ms（接近但低于 12ms 预算）
- 未做掩码缓存（计划文档里的"增量重算"留待优化）

## 灰度开关设计

`useStore.enableAutoTiles: boolean`（默认 `false`）

3 处入口读取同一 flag：
1. **TerrainRenderer**（主游戏渲染）— 已支持
2. **MapPreviewRenderer**（地图选择）— 已支持
3. **MapEditor**（地图编辑）— 已支持
4. **WorkerRenderer**（worker 内游戏渲染）— **未支持**，需要协议扩展

切换 UI：MapEditor 工具栏右侧"地图尺寸"面板下方的 checkbox。

## 当前未实施的项

### 1. WorkerRenderer 集成（Phase 5c）
**原因**：WorkerRenderer 在 Web Worker 内运行，无法直接读 useStore。需要扩展 worker-protocol：

```ts
// 在 WorkerCommand.init 中加：
| { type: 'init'; config: { ...; enableAutoTiles?: boolean } }
```

worker 收到 init 后将 flag 存到 `this.enableAutoTiles`，渲染前判断。

**预估工作量**：1-2 小时（协议 + WorkerRenderer 改造 + 验证）。

### 2. 增量重算（计划文档 Phase 4）
**原因**：当前每帧全量重算所有 cell 掩码。在 100×100 地图上性能仍 OK，但 200×200 地图可能超过 12ms 预算。

**解决方向**：
- `TerrainMaskCache` 缓存（计划文档已设计）
- 鼠标抬起时 `flush()` 失效
- resize 地图时全量 `clear()`

### 3. 美术 review 与 feathering 调优
**原因**：当前 SVG 是程序化生成的"能用"水平，没经过美术 review。
- 草尖长度/方向可能不自然
- 沙粒密度可能过密/过疏
- 水波可能太规则

需要美术对照 [2026-06-07-示例地图autotile-demo-结果](./2026-06-07-示例地图autotile-demo-结果.md) 中的 8 个角点测试位置 review。

### 4. 水/沙岸线运行时混合（计划文档方案 B）
**原因**：24-tile 系统对水-沙岸线的混合处理有限（仅靠 mask 0/1/2/4/8 边变体）。
**改进方向**：在沙岸与水面相邻时，用 canvas 渐变（`createLinearGradient`）叠加浅蓝→沙黄的过渡。

## 已知问题

1. **TERRAINS 颜色与 TerrainTiles.ts 重复定义**：
   - 脚本里写死了草/沙/水/岩的 bg/accent 颜色
   - 如果 `TerrainTiles.ts` 改了颜色，生成的 SVG 不同步
   - 修复方向：让脚本从 `TerrainTiles.ts` 读取 TERRAIN_TILES 常量

2. **autotile-demo 视觉验证缺失**：
   - 未在浏览器实际打开 autotile-demo 验证视觉效果
   - 没有截图对比
   - 阻塞美术 review

3. **build 失败**：
   - `npm run build` 在 worker 模块的 `@/common/math` alias 解析上失败
   - 是预存在问题（与本次改动无关）
   - 但阻塞 CI

## 风险

- **SVG 视觉质量不达预期**：当前是程序化生成的"够用"水平，可能需要 1-2 轮美术 review
- **性能问题**：100×100 地图 OK，200×200 地图可能接近预算
- **灰度策略**：当前默认 false，新功能需要用户手动勾选启用，传播慢
- **WorkerRenderer 未集成**：游戏运行时仍用 legacy 4 地形硬切，与地图选择/编辑器不一致
