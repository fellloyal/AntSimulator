# 2026-06-07-地图地形自动过渡-计划

## 背景

当前地图编辑器中每种地形（草/沙/水/石头）都是独立的 SVG 瓦片，相邻地形之间是硬边（每个 cell 用同一种底色 + 装饰图案）。问题：

- 草地和沙地突然切换，缺少海岸/岸边的渐变
- 水面和草地之间是硬切，看起来像贴图
- 沙地嵌入草地中间看起来像贴块

参考红色警戒等经典 RTS 地图编辑器：相邻地形之间用一套**过渡瓦片（autotile / blending tiles）**自动拼接，边缘根据上下左右邻居的地形类型自动选择过渡形态。

## 目标

实现"autotile / 边缘过渡"机制，让相邻不同地形之间的边界自动呈现合理的过渡形态，无需手工绘制过渡。

## 方案对比

### 方案 A：预生成 4-bit 邻接过渡瓦片（边掩码，16 种）

**思路**：每种地形的 SVG 瓦片拆成 16 种"邻接组合"——根据该格子的上、下、左、右 4 个邻居分别是否是同类地形（共 2^4 = 16 组合），自动选一张对应过渡图。

- 每种地形 16 张子瓦片，4 种地形 = 64 张
- 边过渡效果不错，但**角点（3 种地形交汇）处理粗糙**

### 方案 B：运行时边缘混合（Canvas API）

**思路**：每个 cell 画完后，检查上下左右 4 个邻居，如果地形不同，就在 cell 边缘画一条**过渡色带**（混合色或半透明叠加）。

- 例如草地格子的下边是沙地 → 在 cell 底部 2-4px 范围内画一条草地→沙地的渐变色
- 优点：无需新资源
- 缺点：仅支持 2 种地形间的平滑过渡，**角点处理困难**（3 种地形交汇无法平滑）

### 方案 C：24-tile autotile（边 + 角，推荐）⭐

**思路**：在 16 种边掩码基础上，**额外叠加 4 个角点的细节**，处理"凸角/凹角"形态。

```
主体：4 边（上/下/左/右）是否与中心同地形 → 2^4 = 16 种
角点：4 角（左上/右上/左下/右下）对角是否同地形 → 2^4 = 16 种
实际渲染：base = edgeMask，4 个角各画一个 8x8 小填充（凸出/凹入）
```

**16 种边掩码不够自然的原因**：
举例：草地的右侧格子是**沙地** vs **水**，16 种掩码对这两种情况都返回 `mask=8`，会画同一张子瓦片，无法区分。

而 24-tile 在角点对角匹配时，单独画一个 8x8 的小填充来体现"凸角"和"凹角"差异：
- 草地右上角是水（角对角是草）→ 草地**凹入**角
- 草地右上角是沙（角对角是水）→ 草地**凸出**角

**资源量**：
- 主体瓦片：16 张/地形
- 角点瓦片：4 张/地形（标准 4 角，可旋转复用）
- 总计：4 × 20 = 80 张

**性能**：
- 仍是 O(N) drawImage，每帧绘制 ~100-300ms（基于 100×100 地图的估算）

### 方案 D：47-tile（红警/WC3 标准）

- 47 张子瓦片（4 边 × 8 角 + 中心 + 4 边 + 4 角）
- 美术资源量翻倍
- 角点处理最精细
- 项目当前规模不需要

## 推荐方案：C（24-tile） ⭐

视觉上明显比纯 16 种自然，角点（3 种地形交汇）能正确处理凸/凹角形态。

**资源按地形对优化**：
- **草↔沙**：全套 16 主体 + 4 角（自然渐变，岸滩）
- **草↔水**：全套 16 + 4 角（重点，海岸线）
- **沙↔水**：全套 16 + 4 角（沙滩入海）
- **草↔岩**：8 种（岩是装饰，不需精细）
- **沙↔岩**：8 种

总资源量：3 × 20 + 2 × 8 = 76 张

## 推荐方案：C + B 混合

- **方案 C（24-tile autotile）** 用于**草↔沙**、**草↔水**、**沙↔水**、**草↔岩**、**沙↔岩**之间的过渡（5 种过渡关系）
- **方案 B（边缘渐变）** 用于**水↔沙**（海岸线）的特殊处理（水边浪花/湿润效果）

具体实施：

### Phase 1：autotile 数据结构

```ts
// 邻接掩码：4 位分别表示 [上, 下, 左, 右] 是否是同类
export type EdgeMask = 0..15; // 0=无同类邻居, 1=上, 2=下, 3=上+下, ...

// 角点掩码：4 位分别表示 [左上, 右上, 左下, 右下] 对角是否同类
export type CornerMask = 0..15;

// 每种地形为每个掩码预生成一张过渡子瓦片
export interface TerrainAutoTiles {
  terrainId: string;
  edgeVariants: Record<EdgeMask, string>; // 16 张主体 SVG
  cornerVariants: Record<'tl' | 'tr' | 'bl' | 'br', string>; // 4 张角点 SVG
}

// 角点查表：[edgeMask][cornerMask] -> 是否画角贴片 + 凸/凹
export interface CornerLookup {
  isConvex: boolean; // true=凸角（向外延伸），false=凹角（向内收）
  tile: 'tl' | 'tr' | 'bl' | 'br';
}
```

**生成策略（程序化生成 SVG）**：

对草地（grass）来说：
- 掩码 0（无同类邻居）：纯草地，但边缘有向外扩展的"草尖"，延伸到邻居格子的 ~2px 范围
- 掩码 1（上邻居是草地）：下边缘保持纯草
- 掩码 2（下邻居是草地）：上边缘保持纯草
- 掩码 3（上+下都是草地）：纯草（无边缘变化）
- 掩码 4（左邻居是草地）：右边缘保持
- 掩码 5（上+左）：右下角扩展草
- 掩码 8（右邻居是草地）：左边缘保持
- 掩码 15（全方向都是草地）：纯草

角点：4 张 8x8 SVG 单独画
- 凸角（角对角是同类，但两边都不是）：向外扩展的"齿"
- 凹角（角对角是异类，且两边都是同类）：向内收的"缺口"

### Phase 2：渲染时计算邻接掩码

```ts
function computeEdgeMask(cell: Cell, neighbors: { up, down, left, right }): EdgeMask {
  let mask = 0;
  if (neighbors.up?.terrain === cell.terrain) mask |= 1;  // bit 0
  if (neighbors.down?.terrain === cell.terrain) mask |= 2; // bit 1
  if (neighbors.left?.terrain === cell.terrain) mask |= 4; // bit 2
  if (neighbors.right?.terrain === cell.terrain) mask |= 8; // bit 3
  return mask;
}

function computeCornerMask(cell: Cell, neighbors: { tl, tr, bl, br }): CornerMask {
  let mask = 0;
  if (neighbors.tl?.terrain === cell.terrain) mask |= 1;  // bit 0
  if (neighbors.tr?.terrain === cell.terrain) mask |= 2; // bit 1
  if (neighbors.bl?.terrain === cell.terrain) mask |= 4; // bit 2
  if (neighbors.br?.terrain === cell.terrain) mask |= 8; // bit 3
  return mask;
}
```

每帧绘制时，按 (terrain, edgeMask) 分桶，每桶按 cornerMask 再分桶，主体批量画 + 角点单独画。

### Phase 3：海岸线特殊处理（水↔沙）

水边叠加一层**湿润沙滩**（沙色 + 蓝色水波混合），在水面格子向上下左右是沙地的边缘画 1-2 像素的浅蓝色湿润带。

实现：在水地形渲染后再扫一遍可见区域，对水边格子额外画一条 "beach_wet_edge" 纹理。

### Phase 4：编辑器实时反馈

地图编辑器中画地形时，每帧重新计算邻接掩码（用 ref 缓存 + 局部失效），保证所见即所得。

## 性能评估

- 当前：4 桶 × N cell
- 新：4 地形 × 16 边掩码 × 16 角掩码 = 1024 桶（但实际只有地形边界的格子需要角点处理）
- 实际开销：分桶字典查询 + 角点单独 drawImage，仍在 12ms 帧预算内
- 邻接计算：8 次 map.getByCoords() × N cell，每帧 ~2-3ms（100×100 地图）

## 风险与回退

- **风险 1**：自动生成的子瓦片视觉质量不高 → 保留原始"无过渡"模式作为编辑器开关（默认关闭）
- **风险 2**：地图编辑器中拖动画地形时频繁重算掩码卡顿 → 增量更新：只在 paint/erase 影响的 cell 周围 1 圈重算掩码
- **回退**：保留原 `drawTerrain()` 方法，新方法命名为 `drawAutoTerrain()`，通过 store 开关切换

## 不在本次范围

- 47-tile 全套实现（当前 24-tile 够用）
- 3 种以上地形交汇的角点处理（保持硬切）
- 装饰性元素（树、岩石）在过渡带的摆放
- 季节变化（草地变黄等）
- 地图生成器自动放置地形（目前用户手工编辑）

## 验收标准

- 草地和沙地相邻时，边界自动呈现草尖渐变到沙地的效果，无明显接缝
- 水边草地/沙地时，水面有湿润带效果
- 3 种地形在角点交汇时，能正确区分凸角和凹角形态
- 地图编辑器中拖动画地形时无卡顿（< 1 帧延迟）
- 现有测试场景（纯草地地图）视觉无变化

## 16 变体边掩码可视参考表

位布局：`bit0=上, bit1=下, bit2=左, bit3=右`（值为 1 表示该方向是同类地形）。下表用 `O` 表示中心 cell，`S` 表示同类邻居，`.` 表示不同类邻居。

| 掩码 | 二进制 | 形态 | 渲染要点 |
|---|---|---|---|
| 0  | 0000 | 孤岛（4 邻居全异） | 4 边都需 feathering（草尖/沙粒向外延伸） |
| 1  | 0001 | 顶接 | 仅下/左/右 3 边 feathering |
| 2  | 0010 | 底接 | 仅上/左/右 3 边 feathering |
| 3  | 0011 | 垂直贯通 | 仅左/右 2 边 feathering |
| 4  | 0100 | 左接 | 仅上/下/右 3 边 feathering |
| 5  | 0101 | 顶+左接 | 仅下/右 2 边 feathering |
| 6  | 0110 | 底+左接 | 仅上/右 2 边 feathering |
| 7  | 0111 | 缺右（U+L+D） | 仅右 1 边 feathering |
| 8  | 1000 | 右接 | 仅上/下/左 3 边 feathering |
| 9  | 1001 | 顶+右接 | 仅下/左 2 边 feathering |
| 10 | 1010 | 底+右接 | 仅上/左 2 边 feathering |
| 11 | 1011 | 缺左（U+D+R） | 仅左 1 边 feathering |
| 12 | 1100 | 水平贯通 | 仅上/下 2 边 feathering |
| 13 | 1101 | 缺下（U+L+R） | 仅下 1 边 feathering |
| 14 | 1110 | 缺上（D+L+R） | 仅上 1 边 feathering |
| 15 | 1111 | 全同（内陆） | 无 feathering，纯内部纹理 |

```
掩码 0                掩码 3 (垂直贯通)     掩码 12 (水平贯通)
. . .                 . S .                 . . .
. O .                 . O .                 S O S
. . .                 . S .                 . . .

掩码 5 (顶+左)         掩码 15 (内陆)
. S .                 . S .
S O .                 S O S
. . .                 . S .
```

**对称性利用**：掩码 X 与掩码 Y 关于水平/垂直/180° 旋转等价时，可复用同一张 SVG（如 5↔9↔6↔10，旋转 4 个方向）。这样美术只需出 6 张手工原图（典型形态：孤岛、4 边接、3 边接、2 边相邻、2 边对角、贯通），其余通过 `transform="rotate()/scale(-1,1)"` 派生。

## 角点查表（4 角 × 凸/凹）

每种地形提供 4 张角点子瓦片（tl/tr/bl/br），分两种形态：

- **凸角（Convex）**：中心 cell 的地形"延伸"出尖角，需在角点叠加 8×8 填充块
- **凹角（Concave）**：中心 cell 的地形"退缩"，需在角点反向填补

触发条件（以 TL 角为例，其他 3 角对称）：

| 上邻居 | 左邻居 | TL 对角 | 形态 | 处理 |
|---|---|---|---|---|
| 同类 | 同类 | 同类 | 内角，无处理 | 跳过 |
| 同类 | 同类 | **异类** | **凸角** | 画 `tl-convex` 8×8 角贴片 |
| **异类** | **异类** | 同类 | **凹角** | 画 `tl-concave` 8×8 角贴片 |
| 异类 | 异类 | 异类 | 外角，无处理 | 跳过 |
| 同类 | 异类 | 任意 | 边主导，角点不需特殊处理 | 跳过 |
| 异类 | 同类 | 任意 | 边主导，角点不需特殊处理 | 跳过 |

```ts
// src/render/TerrainAdjacency.ts
export type Corner = 'tl' | 'tr' | 'bl' | 'br';

export function shouldDrawCorner(
  corner: Corner,
  edgeMask: number,
  cornerMask: number,
): { draw: boolean; variant: 'convex' | 'concave' } {
  // 位布局：上=bit0, 下=bit1, 左=bit2, 右=bit3
  // 对角位：TL=bit0, TR=bit1, BL=bit2, BR=bit3
  const edges = {
    tl: { up: 1, left: 4, diag: 1 },
    tr: { up: 1, right: 8, diag: 2 },
    bl: { down: 2, left: 4, diag: 4 },
    br: { down: 2, right: 8, diag: 8 },
  }[corner];

  const upSame = (edgeMask & edges.up) !== 0;
  const sideSame = (edgeMask & edges.left) !== 0;
  const diagSame = (cornerMask & edges.diag) !== 0;

  if (upSame && sideSame && !diagSame) return { draw: true, variant: 'convex' };
  if (!upSame && !sideSame && diagSame) return { draw: true, variant: 'concave' };
  return { draw: false, variant: 'convex' };
}
```

每帧每个 cell 至多画 4 次角点查表（4 角），实际只有地形边界的角点会触发绘制，开销可控。

## SVG 子瓦片生成算法

通过 `scripts/generate-terrain-tiles.mjs` 程序化生成，避免手画 80 张。核心思路：

### 边掩码变体生成

```js
// 输入：基础地形 SVG（32×32，cell 范围 0-32，邻居 0-2px 重叠区）
// 输出：16 张变体 SVG

function generateEdgeVariant(baseSvg, mask) {
  const overlays = [];

  // 对每个"异类"边，叠加 feathering 图案
  if (!(mask & 1)) overlays.push(buildTopFringe(baseSvg.terrainId));    // 上边
  if (!(mask & 2)) overlays.push(buildBottomFringe(baseSvg.terrainId)); // 下边
  if (!(mask & 4)) overlays.push(buildLeftFringe(baseSvg.terrainId));   // 左边
  if (!(mask & 8)) overlays.push(buildRightFringe(baseSvg.terrainId));  // 右边

  return composeSvg(baseSvg, overlays);
}

// 草尖向上/沙粒向下等"自然延伸"图案：用 noise + 路径
function buildTopFringe(terrainId) {
  switch (terrainId) {
    case 'grass': return grassBladesUp();     // 上边缘 2px 高的草尖
    case 'sand':  return sandGrainsUp();      // 沙粒向上散落
    case 'water': return waterRippleUp();     // 浅蓝水波纹
    case 'stone': return stoneCrackTop();     // 石头边缘碎裂纹
  }
}
```

### 角点贴片生成

8 张角点子瓦片（4 角 × 凸/凹）单独生成：

```js
function generateCornerVariants(terrainId) {
  return {
    'tl-convex': buildCornerFringe(terrainId, 'tl', 'convex'),
    'tl-concave': buildCornerFringe(terrainId, 'tl', 'concave'),
    'tr-convex': buildCornerFringe(terrainId, 'tr', 'convex'),
    'tr-concave': buildCornerFringe(terrainId, 'tr', 'concave'),
    // ... bl, br 同理
  };
}
```

### 输出格式

- 每个变体导出为独立 SVG 字符串，写入 `src/render/assets/TerrainAutoTiles.ts`（编译期 import）
- `AssetRegistry.preloadSVG()` 在启动时一次性加载 80 张到内存位图
- 运行时按 `(terrain, edgeMask, cornerVariant)` 三元组查找

### 美术验证

生成后导出 PNG 对照表 `docs/terrain-autotile-preview.png`，美术对照 16 边 + 8 角逐张检查 feathering 自然度。

## 编辑器增量重算策略

地图编辑器中拖动画地形是高频操作（鼠标移动事件 ~60Hz），每帧全量重算掩码会超 12ms 预算。增量策略：

### 1. 脏区矩形追踪

```ts
class PaintSession {
  private dirtyRect: { x0: number; y0: number; x1: number; y1: number } | null = null;

  // 每次 paint/erase cell
  markDirty(x: number, y: number) {
    if (!this.dirtyRect) {
      this.dirtyRect = { x0: x, y0: y, x1: x, y1: y };
    } else {
      this.dirtyRect.x0 = Math.min(this.dirtyRect.x0, x);
      this.dirtyRect.y0 = Math.min(this.dirtyRect.y0, y);
      this.dirtyRect.x1 = Math.max(this.dirtyRect.x1, x);
      this.dirtyRect.y1 = Math.max(this.dirtyRect.y1, y);
    }
  }

  // 鼠标抬起时统一失效
  flush() {
    if (!this.dirtyRect) return;
    const { x0, y0, x1, y1 } = this.dirtyRect;
    // 失效范围向外扩 1 cell（邻居掩码受中心 cell 影响）
    for (let y = y0 - 1; y <= y1 + 1; y++) {
      for (let x = x0 - 1; x <= x1 + 1; x++) {
        this.maskCache.invalidate(x, y);
      }
    }
    this.dirtyRect = null;
  }
}
```

### 2. 掩码缓存

```ts
class TerrainMaskCache {
  private cache = new Map<number, { edge: number; corner: number }>();

  private key(x: number, y: number): number {
    return y * 10000 + x; // 假设地图 ≤ 10000 列
  }

  invalidate(x: number, y: number) {
    this.cache.delete(this.key(x, y));
  }

  get(x: number, y: number, grid: WorldGrid) {
    const k = this.key(x, y);
    const hit = this.cache.get(k);
    if (hit) return hit;

    const cell = grid.getCell(x, y);
    if (!cell) return { edge: 0, corner: 0 };

    const edge = computeEdgeMask(cell, grid, x, y);
    const corner = computeCornerMask(cell, grid, x, y);
    this.cache.set(k, { edge, corner });
    return { edge, corner };
  }
}
```

### 3. 帧预算分配（100×100 地图）

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 鼠标事件 → markDirty | < 0.1ms | 仅记脏区 |
| flush() → 失效掩码 | < 0.5ms | 100~200 cell × 1 圈 |
| render() → 查掩码 | 2-3ms | 全图遍历，已缓存 |
| drawImage 角点 | 0.5-1ms | 仅边界 cell |
| **合计** | **< 5ms** | 远低于 12ms 预算 |

### 4. 关键约束

- **不在 drag 过程中 flush**：鼠标移动事件累积到 dirtyRect，鼠标抬起 / 出画笔范围时才 flush
- **不在 rAF 之外读取 cache**：render() 在 rAF 中调用，保证 cache 一致性
- **resize 地图时全量失效**：`grid.setSize(w, h)` 后调用 `maskCache.clear()`

## 迁移与灰度开关

### Feature Flag

```ts
// src/store/useStore.ts
interface UIStore {
  enableAutoTiles: boolean;  // 默认 false，灰度启用
  setEnableAutoTiles: (v: boolean) => void;
}
```

### 渲染分支

```ts
// src/render/TerrainRenderer.ts
class TerrainRenderer {
  drawTerrain(grid: WorldGrid, vp: Viewport) {
    if (useStore.getState().enableAutoTiles) {
      this.drawAutoTerrain(grid, vp);   // 24-tile 路径
    } else {
      this.drawTerrainLegacy(grid, vp); // 原 4 色硬边路径
    }
  }
}
```

三处渲染入口（地图编辑器、地图选择预览、主游戏视图）都走同一个开关，行为一致。

### 地图编辑器工具栏

在右侧"地图尺寸"面板下方加一个开关：

```tsx
<label className="flex items-center gap-2 text-sm">
  <input
    type="checkbox"
    checked={enableAutoTiles}
    onChange={(e) => setEnableAutoTiles(e.target.checked)}
  />
  自动地形过渡（24-tile）
</label>
```

默认未勾选，地图选择预览也跟随。

### 4 阶段灰度发布

| 阶段 | 范围 | 验收 |
|---|---|---|
| Phase 1 | 资源生成 + 渲染实现，`enableAutoTiles=false` | 旧路径无回归，构建通过 |
| Phase 2 | 开发者本机手动勾选，肉眼检查 5 种地形对的视觉 | 边/角过渡自然，无硬切 |
| Phase 3 | 灰度默认开启（`enableAutoTiles=true`），10 张测试地图全量回归 | 帧率 ≥ 50fps（< 20ms/帧） |
| Phase 4 | 移除 `drawTerrainLegacy()`，删除 feature flag，发布正式版 | 资源从 4 张地形图缩减为 4 套地形（80 张子瓦片），用户无感 |

### 回退条件

- 任一地图帧率降至 30fps 以下 → 立即回退到 `false`
- 美术 review 任意地形对过渡不通过 → 阻塞 Phase 2，不进入 Phase 3
