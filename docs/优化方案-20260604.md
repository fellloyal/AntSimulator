## 已实施优化详情

### 一、ImageData 批量像素渲染

**修改文件**: `src/render/WorldRenderer.ts`

**变更内容**:
- 将逐格 `ctx.fillRect()` + `rgb(r,g,b)` 字符串拼接替换为 `ImageData` 直接写像素
- 使用 `OffscreenCanvas` + `putImageData` + `drawImage` 缩放绘制
- 缓存蚁群 RGB 值，避免每帧解析 hex 颜色
- 1 像素 = 1 cell，由浏览器做缩放插值

**效果**: 消除了 129,600 次 fillRect 调用和字符串拼接，大幅减少 GC 压力

### 二、兵蚁采样优化

**修改文件**: `src/simulation/SoldierUpdater.ts`

**变更内容**:
- 引入双触角采样（与工蚁一致的 Phase 1 + Phase 2 策略）
- 随机探索采样从 64 次降至 12 次
- 采样角度范围从 PI*0.7 缩窄至 PI*0.6
- 新增 `TURN_STRENGTH = 4.0` 的触角转向强度

**效果**: 兵蚁采样开销降低约 75%，同时保持寻路质量

### 三、蚂蚁数组优化

**修改文件**: `src/simulation/Colony.ts`

**变更内容**:
- `removeDeadAnts()`: 从 `Array.filter()` 改为 swap-and-pop 原地删除
- 新增 `_soldiersCount` 缓存字段，在 `specializeSoldier()` 时 +1，`removeDeadAnts()` 时 -1
- `soldiersCount()` 直接返回缓存值，不再遍历全量蚂蚁

**效果**: 消除每帧创建新数组的 GC 开销，soldiersCount 从 O(N) 降至 O(1)

### 四、战斗系统优化

**修改文件**: `src/simulation/FightSystem.ts`

**变更内容**:
- 新增帧计数器，完整战斗扫描每 3 帧执行一次
- 非扫描帧仅处理 pending fight requests 和互绑检查
- 跳过已战斗蚂蚁和 `Worker + NoFight` 蚂蚁的遍历

**效果**: 战斗检测开销降低约 66%，对非战斗场景几乎零开销

### 五、Web Worker 离线模拟

**新增文件**:
- `src/simulation/worker-protocol.ts` — 主线程/Worker 通信协议
- `src/simulation/simulation-worker.ts` — Worker 入口，运行模拟循环
- `src/render/WorkerRenderer.ts` — 从 Worker 数据渲染的渲染器

**修改文件**:
- `src/hooks/useSimulation.ts` — 支持 Worker/主线程双模式
- `src/hooks/useCanvas.ts` — 支持 Worker 模式下的交互
- `src/App.tsx` — 传递 worker refs

**架构**:
```
Worker 线程:
  Simulation.update(dt) → serializeAnts() + serializeWorld()
  → postMessage({antData, worldData}, [Transferable])
  → requestAnimationFrame(loop)

主线程:
  onmessage → 缓存 Float32Array
  → WorkerRenderer.render(ctx, antData, worldData)
  → requestAnimationFrame(renderLoop)
```

**数据格式**:
- 蚂蚁数据: 每只 8 float (x, y, angle, phase, type, wobble, dyingTimer, isPaused)
- 世界数据: 每 cell 4 float (wall|food_packed, r_norm, g_norm, b_norm)

**特性**:
- `USE_WORKER = true` 开关，Worker 创建失败自动降级到主线程
- 工具交互（添加食物/墙壁/蚁群）通过 `postMessage` 发送到 Worker
- 视口平移/缩放在主线程处理，不影响 Worker

### 六、信息素离屏 Canvas 缓存

**集成到 ImageData 方案中**: WorldRenderer 使用 OffscreenCanvas 缓存，只在尺寸变化时重建。
